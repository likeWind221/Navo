# F4 过程 UI 实施方案（以 LobeHub 为基准）

## 1. 目标行为

一次 Agent 回合分为“处理状态”“过程”和“结果”三层。顶部状态行只表达本回合是否仍在处理以及累计用时，不再根据当前思考或工具活动动态改标题；思考、工具调用与中间说明按真实发生顺序展示在过程区；最终回答始终位于过程区之后并独立可见。

展开状态下的目标布局固定为：

```text
处理中 4s                    ← 回合结束后变为“已处理 12s”
────────────────────
思考中 / 思考摘要
执行 Shell
思考中 / 思考摘要
执行 Shell
────────────────────         ← 折叠 / 展开上方处理过程
最终回答
```

回合结束并自动折叠后：

```text
已处理 12s
────────────────────         ← 可再次展开处理过程
最终回答
```

三条验收行为：

1. **顶部状态稳定。** 生成中始终显示“处理中 {已用时间}”，不随 reasoning、Shell 或其他工具切换而跳动；进入终态后固定为“已处理 {总用时}”。
2. **过程按真实顺序累积。** reasoning 与工具活动分别形成独立过程行，例如“思考中 / 思考摘要 → 执行 Shell → 思考中 / 思考摘要 → 执行 Shell”，历史步骤不会被当前活动标题覆盖。
3. **折叠边界位于最终回答之前。** 回合结束后，上方思考与执行过程整体可折叠，最终回答永远不进入折叠区域；顶部“已处理 {总用时}”仍可见。

## 2. 分层设计

原方案把“当前活动动态标题”放在过程头部。F4.3 现改为稳定状态栏 + 顺序过程流，因此按当前项目规模收敛为以下层次：

| 层 | 职责 | 输入 → 输出 | 位置 |
|---|---|---|---|
| 回合分组 | 判断哪些内容块属于过程、哪一块是最终回答；判断本次回合是否满足折叠条件 | `AssistantContentBlock[]` + 回合状态 → `{ process, final, foldable }` | `frontend/src/workspace/chat/process.ts` |
| 状态与用时 | 只生成“处理中 Ns / 已处理 Ns”；不读取当前工具或 reasoning 内容生成动态标题 | 回合状态 + `startedAt/endedAt` + 当前时间 → 状态文案 | `frontend/src/workspace/chat/process/status.ts` |
| 过程行容器 | 负责顶部状态、过程区展开状态、结束后的自动折叠与最终回答前的折叠边界 | 过程内容块 + 回合状态 → 界面 | `frontend/src/workspace/chat/process/Row.tsx` |
| 内容块呈现 | 按真实顺序渲染 reasoning、工具和中间说明；reasoning 在活动时显示“思考中”，阶段稳定后显示可读摘要 | 单个内容块 → 过程条目 | `frontend/src/workspace/chat/process/Block.tsx` |
| 行级呈现 | 工具行与通知行后续共用“图标 + 描述 + 状态 + 用时”结构 | 单个工具或命令 → 界面 | `frontend/src/workspace/chat/process/Tool.tsx`、`process/Notice.tsx` |
| 图标库 | 自绘状态图标，不引入图标依赖 | 图标名 → SVG | `frontend/src/ui/Icon.tsx`、`frontend/src/ui/icon/**` |

依赖方向保持单向：`List.tsx` → `process/Row.tsx` → `process/Block.tsx` / `process/Tool.tsx` / 图标库；状态文案和 reasoning 摘要推导应保持纯函数，可单独测试。

## 3. 状态与生命周期

### 3.1 顶部状态行

顶部只承担回合级状态，不承担当前活动说明：

- 等待或生成中：`处理中 {elapsed}`，例如 `处理中 4s`。
- completed / cancelled / failed / truncated 等终态：`已处理 {duration}`，例如 `已处理 12s`。
- 已用时间从 `startedAt` 起实时更新；终态后使用 `endedAt - startedAt` 固定，不继续跳动。
- 失败、取消、截断的具体语义继续由对应过程条目或错误提示表达，不通过不断改变顶部标题承载。

因此 F4.3 **取消原“当前活动动态标题”要求**：顶部不再显示“正在分析……”“正在执行 Shell……”等随流变化的标题，也不需要从 reasoning 首句或 Markdown 标题推导回合标题。

### 3.2 顺序过程流

过程区忠实保留 Agent 的执行轨迹：

```text
Reasoning A → Tool A → Reasoning B → Tool B → ... → Final Answer
```

展示规则：

- 正在流式产生的 reasoning 行显示 `思考中`；当这一段 reasoning 已不再是当前活动时，可显示其稳定摘要。
- reasoning 摘要只用于概括**该段思考本身**，不替代顶部状态。摘要优先取可读标题，其次取首句并按语法边界截断；没有稳定内容时保留通用“思考过程”。
- 工具活动直接显示动作，例如 `执行 Shell`；后续其他工具按统一显示名映射为 `执行 {工具名}`。
- 同一回合出现多段 reasoning / 多次工具调用时，每段都保留自己的位置，不合并成一个不断变化的“当前状态标题”。
- 中间说明仍按事件顺序进入过程区，不进入最终回答。

### 3.3 折叠生命周期

沿用 F4.2 已确认的自动折叠语义，但调整折叠控件的位置：

- 回合处于等待或生成中：过程保持展开，不允许折叠，便于观察实时执行轨迹。
- 回合结束且存在最终回答：若用户未手动接管展开状态，过程区自动折叠。
- 回合结束后用户可以通过**最终回答上方的折叠边界**重新展开 / 折叠上方过程。
- 顶部“已处理 {总用时}”不随过程区隐藏，折叠后仍可见。
- 用户手动展开过的已结束回合保持展开，不再被自动折叠。
- 回合只有过程、没有最终回答（例如纯工具回合）：不折叠，避免只剩状态栏和孤立分隔线。

折叠判定仍同时满足“回合已进入终态”“存在可展示的最终回答”“过程段非空”。最终回答永远在折叠区域之外。

## 4. 图标库

延续 F1.2.1 确定的“视觉自定义、不引入图标库”基线，把现有三枚图标扩展成自绘图标库：

- 入口保持 `frontend/src/ui/Icon.tsx`，对外只暴露 `Icon` 组件与图标名联合类型；使用方只写 `<Icon name="..." />`，不直接引用单图标文件。
- 每个图标一个 PascalCase 组件文件，放在 `frontend/src/ui/icon/`；现有 `arrow`、`book`、`guide` 一并迁入，图标名不变。
- 统一视觉参数：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="1.75"`、圆头圆角连接、`aria-hidden`，颜色一律继承文字颜色。
- 本阶段新增：`brain`（思考）、`tool`（工具）、`loader`（进行中，配合旋转动画）、`check`（成功）、`close`（失败或取消）、`chevron`（展开折叠指示）。
- 图标不承载语义逻辑：状态到图标的映射写在呈现层，图标文件只负责画形状。

## 5. 与参考实现的差异

受当前阶段范围与新的消息布局影响，以下能力明确不采用，需要时后续单独规划：

- 不引入 LobeHub 依赖的 `motion`、`antd-style`、`i18next`、`zustand`；动画与样式使用现有 CSS Module 与 `tokens.css`。
- 不做工具授权干预、中止确认、多 Agent 议会、消息分支与虚拟滚动。
- 不再复刻 LobeHub 的“当前活动驱动顶部 headline”机制。Navo 的顶部保持稳定的回合级“处理中 / 已处理 + 用时”，当前活动由下方逐条过程记录承担。
- reasoning 摘要仍可从内容中提取，但它属于对应 reasoning 行，不会上升为整个回合的标题。
- LobeHub 把过程折叠做成独立的 `ProcessFold` 与 `WorkflowCollapse` 两级结构；本项目保持单个过程容器，并把折叠交互放在最终回答之前的过程边界。
- 用时来自回合开始与结束的时间戳，由调用方注入时间后写入会话状态，保证 reducer 可测试；不引入后端耗时字段，协议保持不变。

## 6. 明确不做

- 不修改 `agent.turn.v2`、`session.command.v1` 等公共契约，不改后端与 `frontend/shared/`。
- 不引入组件库、图标库、动画库。
- 不改动消息滚动区、输入区遮挡与水平对齐等 F3.8/F3.9 已验收布局。
- 不做多会话、持久化与历史回放。
- F4.3 不负责把工具卡片和通知行彻底统一；这一部分仍由 F4.4 承接。

## 7. 验证方式

- 纯函数测试覆盖：进行中 / 已结束用时格式、reasoning 摘要、空 reasoning、多段 reasoning 与多工具顺序。
- 组件测试覆盖：顶部状态在工具切换时不跳标题；elapsed time 生成中更新、终态冻结；生成中过程展开；结束后过程自动折叠；通过最终回答前边界重新展开；纯工具回合不折叠。
- Electron 桌面验收：真实模型回合至少覆盖“思考 → Shell → 思考 → Shell → 最终回答”，确认过程条目顺序稳定、顶部仅显示“处理中 Ns / 已处理 Ns”、折叠后最终回答始终可见，窄窗口下长内容不溢出。

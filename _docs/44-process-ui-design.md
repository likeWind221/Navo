# F4 过程 UI 实施方案（以 LobeHub 为基准）

## 1. 目标行为

一次 Agent 回合分为“过程”和“结果”两部分：思考、工具调用、中间说明属于过程，最终回答属于结果。

```text
回合开始
   |
   +-- 过程（思考 / 工具 / 中间说明）    结果（最终回答）
   |      |                                  |
   |      +-- 生成中：展开，行标题随当前活动变化，显示已用时间
   |      |
   |      +-- 结束后：折叠成一行摘要 + 总用时（用户手动展开过则保持展开）
   |                                          |
   v                                          v
[过程行] <--------------------------------> [回答正文，始终可见]
```

三条验收行为：

1. 生成中过程可见并自述当前活动，不再固定显示“思考中”。
2. 回合结束后过程整体折叠为一行，摘要包含用时与工具数量。
3. 最终回答不进入折叠区域，任何状态下都独立可见。

## 2. 分层设计

参考 LobeHub 的 `Group` / `WorkflowCollapse` / `ProcessFold` / `toolDisplayNames` 四层，按当前项目规模收敛为三层加一层图标库。

| 层 | 职责 | 输入 → 输出 | 位置 |
|---|---|---|---|
| 回合分组 | 判断哪些内容块属于过程、哪一块是最终回答；判断本次回合是否满足折叠条件 | `AssistantContentBlock[]` + 回合状态 → `{ process, final, foldable }` | `frontend/src/workspace/chat/process.ts` |
| 标题推导 | 由当前最后一块内容推导生成中标题；生成结束摘要与用时文案 | 内容块 → 标题字符串 | `frontend/src/workspace/chat/process/headline.ts` |
| 过程行 | 持有展开状态、计时与渲染顺序；流式展开、结束折叠 | 过程内容块 + 回合状态 → 界面 | `frontend/src/workspace/chat/process/Row.tsx` |
| 内容块呈现 | 过程段内部按顺序渲染思考、工具与中间说明 | 单个内容块 → 界面 | `frontend/src/workspace/chat/process/Block.tsx` |
| 行级呈现 | 工具行与通知行共用同一套“图标 + 描述 + 状态 + 用时”结构 | 单个工具或命令 → 界面 | `frontend/src/workspace/chat/process/Tool.tsx`、`process/Notice.tsx` |
| 图标库 | 自绘状态图标，不引入图标依赖 | 图标名 → SVG | `frontend/src/ui/Icon.tsx`、`frontend/src/ui/icon/**` |

依赖方向单向：`List.tsx` → `process/Row.tsx` → `process/Tool.tsx`、`process/Notice.tsx`、图标库；分组与标题推导是纯函数，不依赖 React，可单独测试。

## 3. 状态与生命周期

展开状态由过程行自己持有，规则来自 LobeHub 的 `WorkflowCollapse` 与 `ProcessFold`：

- 回合处于等待或生成中：始终展开，忽略用户此前的折叠动作。
- 回合结束且用户从未手动切换过展开状态：折叠。
- 回合结束但用户手动展开过：保持展开，不再自动折叠。
- 回合结束后统一折叠为“已处理 {用时}”（用户确认的文案），工具数量不进入折叠行，展开后仍可见。
- 回合只有过程、没有最终回答（例如纯工具回合）：不折叠，避免只剩一个孤立标题。

折叠判定必须同时满足“回合已进入终态”“存在可展示的最终回答”“过程段非空”，与 LobeHub `shouldFoldProcess` 的条件一致。停止、失败、截断同样属于终态，折叠后仍保留对应的状态图标与错误文案。

## 4. 图标库

延续 F1.2.1 确定的“视觉自定义、不引入图标库”基线，把现有三枚图标扩展成自绘图标库：

- 入口保持 `frontend/src/ui/Icon.tsx`，对外只暴露 `Icon` 组件与图标名联合类型；使用方只写 `<Icon name="..." />`，不直接引用单图标文件。
- 每个图标一个 PascalCase 组件文件，放在 `frontend/src/ui/icon/`；现有 `arrow`、`book`、`guide` 一并迁入，图标名不变。
- 统一视觉参数：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="1.75"`、圆头圆角连接、`aria-hidden`，颜色一律继承文字颜色。
- 本阶段新增：`brain`（思考）、`tool`（工具）、`loader`（进行中，配合旋转动画）、`check`（成功）、`close`（失败或取消）、`chevron`（展开折叠指示）。
- 图标不承载语义逻辑：状态到图标的映射写在呈现层，图标文件只负责画形状。

## 5. 与 LobeHub 的差异

受当前阶段范围影响，以下能力明确不采用，需要时后续单独规划：

- 不引入 LobeHub 依赖的 `motion`、`antd-style`、`i18next`、`zustand`；动画与样式使用现有 CSS Module 与 `tokens.css`。
- 不做工具授权干预、中止确认、多 Agent 议会、消息分支与虚拟滚动。
- LobeHub 从思考内容的 Markdown 标题取流式标题，取不到就回退通用文案；当前模型的思考内容多为连续段落，因此标题推导按“思考内容最后一级标题 → 思考内容首句（按语法边界截断） → 通用文案”三级回退。
- LobeHub 把过程折叠做成独立的 `ProcessFold` 与 `WorkflowCollapse` 两级结构；本项目只有单次模型请求或简单多步，收敛为单个过程行组件。
- 用时来自回合开始与结束的时间戳，由调用方注入时间后写入会话状态，保证 reducer 可测试；不引入后端耗时字段，协议保持不变。

## 6. 明确不做

- 不修改 `agent.turn.v2`、`session.command.v1` 等公共契约，不改后端与 `frontend/shared/`。
- 不引入组件库、图标库、动画库。
- 不改动消息滚动区、输入区遮挡与水平对齐等 F3.8/F3.9 已验收布局。
- 不做多会话、持久化与历史回放。

## 7. 验证方式

- 纯函数（回合分组、标题推导、用时格式化）用单元测试覆盖：多步工具、思考后直接回答、纯工具回合、空内容、中英文截断边界。
- 组件测试覆盖：生成中展开、结束后折叠、手动展开后不自动折叠、停止与失败状态保留。
- Electron 桌面验收：真实模型回合中观察标题变化与结束折叠，窄窗口下长工具参数与长通知不溢出。

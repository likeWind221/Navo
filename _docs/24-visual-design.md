# SkillWorld 视觉设计规范

**版本：v1.1 · 山丘远征站（地图后续采用 3D 建模）**
**状态：视觉实施基线已确定，页面实现与视觉验收尚未完成。**

本文件是前端视觉单一事实源，不另建重复的 `design.md`。后续调整在此修订；信息架构仍以 `21-frontend-information-architecture.md` 为准。

## 1. 已选方向

用户选择原型 C：**山丘远征站**。亮白、暖砂、低饱和陶土色，结合六边形地形与战棋探索意象；这是学习工作区，不是战斗 HUD，也不是传统课程后台。

本规范保留已选视觉方向，替代已删除的三版原型代码。具体组件仍需在 F1.2 中实现与验收，不代表界面功能已完成。

## 2. 视觉原则

- 内容为主，游戏感来自地形、旗帜、地图坐标和空间层次，不来自金币、经验条或虚构成就。
- 白色卡片、轻描边、宽松留白；不用暗色控制台、霓虹、厚重金属框或大面积高饱和色。
- 教材与练习是同一个 Node 的内容，右侧向导是唯一 NodeSession 对话。
- 探索引导不是系统执行进度，生成教材不等于能力掌握；完成与 mastery 必须来自对应事实。
- 地形是节点身份，不自动映射难度、掌握状态或前置关系；这些语义需要后续产品确认。

## 3. 颜色 Token

以下为选中原型的视觉基线；浅色辅助文字须在落地时提高对比度，而不是机械照抄原型。

| 语义 | 基线值 | 用法 |
|---|---|---|
| canvas | `#fffefa` | 全局暖白画布 |
| surface | `#ffffff` | 教材、任务卡片 |
| surface-warm | `#fffdf9` | 对话面板 |
| surface-muted | `#faf3ea` | 选中任务、浅底提示 |
| text | `#554b40` | 标题与正文主色 |
| text-secondary | `#756958` | 可读辅助文字，替代原型过浅灰色 |
| text-decorative | `#a19788` | 仅非必要装饰，不用于重要标签 |
| accent | `#bb8663` | 旗帜、强调线、装饰图形 |
| accent-strong | `#805536` | 可交互文字、主要按钮背景，需验证对比度 |
| border | `#eee6db` | 卡片轻描边 |
| border-active | `#d9bfa6` | 选中轮廓，配合文字/图标，不只靠颜色 |
| terrain | `#eee8d7` | 普通六边形地块 |
| terrain-active | `#e3d9bd` | 当前地块 |
| terrain-edge | `#cabea2` | 地块厚度与阴影面 |
| mountain | `#b9b4a7` | 山体低饱和色 |

错误、成功、警告另设语义 token，与地形配色分离。普通文字目标 WCAG AA 4.5:1；大文字和必要非文字控件目标 3:1，正式实现时实际测量。

## 4. 字体与尺寸

- 页面主标题：中文宋体/衬线回退，桌面 32–36px，窄屏 24–28px，常规字重。
- 正文与交互：系统无衬线中文字体，正文 14–16px、行高 1.8–2；避免原型 11px 正文进入正式界面。
- 面板标题：16–20px；辅助标签 12–13px；装饰英文眉题可 10–11px，不能承担唯一信息。
- 代码独立使用等宽字体，例如 Consolas、ui-monospace；不把宋体当作 monospace。
- 正文阅读列约 60–75 个拉丁字符宽；长代码在块内横向滚动，不撑破布局。

## 5. 布局与节奏

**当前实施范围覆盖：** 用户最新要求 F1.2.2 只呈现 SKILLWORLD 品牌顶部栏与干净的 Agent 对话区，左侧导航预留可选插槽但不显示空栏。下列节点标题、探索卡、教材/练习双栏为未来参考，不在当前实现；对话仅本地添加用户消息，未连接时明确提示，不伪造回复。

```text
AppShell（应用外壳）
├─ NavigationRail（窄导航栏）
└─ NodeWorkspace（节点工作区）
   ├─ Breadcrumb（面包屑）
   ├─ NodeHero（节点目标与六边形地形）
   ├─ ExplorationGuide（横向探索引导卡片）
   └─ WorkspaceBody（内容主体）
      ├─ ContentPanel（教材/练习切换面板）
      └─ NodeConversation（统一对话面板）
```

- 导航栏约 72px，页面外边距 24–40px；基础间距刻度 4/8/12/16/24/32/40。
- Hero 使用约 24px 圆角、浅暖色渐变与右侧六边形插画；阅读时可收敛高度，不占满首屏。
- Hero 参考高度 220–260px；首次进入至少可见正文开头及对话入口。
- 三张探索卡横排：阅读地形、搭建营地、回顾发现。措辞是引导，不伪造阶段状态。
- 内容面板占剩余主宽度，对话宽度约 320–380px，栏间距 24px。
- 卡片圆角 16–20px，输入框 10–12px；阴影轻微，依赖层级而非浮空效果。
- 参考验收尺寸 1440×900、1280×800、960×640 和浏览器 390×844。
- 中等宽度缩小装饰与外边距；窄屏采用“教材/练习/对话”切换而非三个被挤窄的栏。
- 内容与对话独立滚动，输入区保持可见；面板切换不丢失草稿或上下文。

## 6. 六边形地形语言

- 地图地块后续采用用户规划的 3D 建模，不在当前样板中制作 SVG 地块或地图替代插画；3D 资源格式、渲染引擎与交互另行设计。
- 地形仍以低多边形/轻等距六边形、薄侧面、柔和阴影为美术方向，此处不锁定 3D 技术实现。
- 当前节点用一面陶土色小旗标识；选择态加清晰描边，不只改变填充色。
- Node 页面只显示当前地块的概念插画，邻接装饰必须明确非真实拓扑，不暗示不存在的节点依赖。
- 后续 DAG 地图可沿用形状、材质与配色，但边、选择、缩放、键盘操作和图版本属于未来单独设计。
- 正式图标全部自行设计为 SVG，暂不引入 Lucide、Phosphor 或其他图标库，不使用 Unicode/emoji 拼接导航。

### 自绘图标规范

- 通用操作图标使用 24×24 viewBox、默认 1.75px 描边、圆角端点与连接，使用 currentColor；典型显示尺寸为 20/24px。
- 图标的光学重心与有效面积保持一致，使用简单几何；不为了六边形主题把所有操作图标都画成六边形。
- 第一批仅按界面需要制作：营地、地图、手册、练习、向导、设置、返回、发送、展开/收起；不提前建立完整图标全集。
- 通用图标默认单色；地形插画允许主题内多色填充与侧面阴影，二者不混用同一尺寸/描边规则。
- 交互图标放入原生 button 并由按钮提供可访问名称；图标本身不重复朗读，装饰 SVG 不进入键盘焦点。
- 图标源文件与地形资产按职责分开组织，只共享必要尺寸/颜色约定，不建立无实际需求的图标注册框架。

## 7. 组件状态与交互

- 教材面板：标题、revision、正文、来源；来源可访问性与打开权限在桌面边界处理。
- 练习面板：题目与后续作答入口；隐藏参考答案不得进入学习者数据，不用 CSS 隐藏代替脱敏。
- 对话：简洁向导消息、浅暖用户消息；状态行独立于内容，工具和错误不假装成自然语言回答。
- Composer（输入区）：使用紧凑两行文本区、浅色边框（border token），点击时不显示包围整个容器的 focus-within 外环；按钮仍保留键盘焦点提示。Enter 提交、Shift+Enter 换行，中文输入法组合阶段不得误提交；真实发送尚未接入时，禁用真实发送或明确标注仅本地添加消息。
- 用户在底部时跟随新消息，向上阅读时不强制拉回；提供“返回最新”入口。
- loading 用骨架或不定进度；empty 提供真实可用下一步；error 保留旧内容并提供重试。
- cancelled 仅表示当前请求终止，不清空已确认内容；offline 与 empty 不混为一谈。
- 不通过模拟百分比暗示真实 Agent 任务进度；错误不能仅短暂闪现后消失。

## 8. 动效与可访问性

- 悬停、选中和面板切换参考 120–200ms，使用透明度和轻位移，不使用持续漂浮地形干扰阅读。
- 遵循 prefers-reduced-motion；焦点清晰、按钮有名称、状态有文字、触控目标建议至少 44px。
- 装饰 SVG 对读屏隐藏；若承载节点信息，则提供简短文本替代。
- 重新连接、加载内容与新消息不抢占焦点；主题 token 本身不能替代对比度检查。

## 9. 实施边界

### 技术基线

- React + TypeScript；语义 CSS 变量集中管理色彩、字体、间距、圆角、阴影和动效时长。
- 全局样式只负责基础重置与 tokens，组件使用 CSS Modules 隔离；不引入 Tailwind。
- 操作图标自绘 SVG；地形后续通过 3D 建模实现，本阶段不制作地图资产。基础控件采用语义 HTML + 自定义视觉，暂不引入图标库或组件库。
- 简单交互仅用 CSS transition/animation；暂不引入 GSAP 或 Motion，并提供减少动态效果模式。
- 不为追求纯自定义而手写复杂焦点陷阱；当前不做复杂弹窗/选择器，未来确有需要时再单独评估原生能力或无样式交互库。
- 组件按职责拆分，每个手写代码文件不超过 300 行。

### 当前阶段的实施顺序

1. **视觉基础与样板**：tokens、三个自绘操作图标、按钮/卡片/标签/输入框/消息样板，先确认整体一致性；不制作六边形地块。
2. **最小对话工作区**：品牌顶部栏、可选导航插槽与对话主体；仅本地输入、添加消息，不包含节点标题、教材/练习或预设 Agent 回复。
3. **状态与响应式验收**：内容切换、草稿保留、空态/加载/失败样例、窄屏切换、独立滚动、键盘焦点、减弱动效和截图核对。

每一步先审查再继续，不一次性实现整个后续阶段。样板不是对用户开放的产品路由；演示数据不进入生产默认组合。

当前不实现整体 DAG 地图、真实导航、发送、批改、流式数据、虚拟列表、Markdown 渲染器或 IPC。未来交互原则不等于本阶段已实现能力。

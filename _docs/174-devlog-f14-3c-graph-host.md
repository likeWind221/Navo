# F14.3c 正式 Host 显式图谱抽取配置

## 做了什么

- 正式 Host 仅在同时指定 `GRAPH_PROVIDER` 与 `GRAPH_MODEL` 时启用图谱抽取；Main 与图谱分别路由，不因 Main 已有模型而默认抽取。
- `resource.graph-status.v1` 按请求顺序返回项目内当前资料的未建立、处理中、可读、失败、过期状态；不可用资料不泄漏代次，未配置与已有图谱可读分别表达。只交付状态，不返回实体关系或正文。
- 保留当前语义配置的图谱复用、失败记录与中断恢复；前端 Bridge 和搜索页面另由 F7.4 消费。

## 关键决策

- Host 为图谱使用独立模型路由名，兼容性仍记录真实提供方、模型与生成预算，连接地址和密钥不进入持久语义配置。相同连接可复用适配器；Qwen 图谱改用另一端点时不继承 Main 密钥。
- 输入预算 2048–131072，输出预算 256–16384；Qwen 默认最大输出为 `min(4096, 输出预算)`，显式值不得超过输出预算。OpenAI 订阅图谱使用账号，不接受 Qwen 专属连接参数。
- 状态读取复用当前资料/正文/索引兼容性判断；没有抽取配置仍能读取兼容的已有图谱。仅有旧构建（含 superseded）返回 stale，不能误报从未建立。

## 坑与发现

- 主编排审查修正了预算下限、旧构建状态遗漏和内部路由名污染兼容性的问题。
- 首轮外部 QA 在主动关闭处理中连接后，用变化中的全局模式判断预期断开，产生脚本线程异常；保留首轮结果，改为请求自身的模式后重跑。未修改生产逻辑或添加重试。
- `config.ts` 243 行、Host 入口及其余新增生产文件均未超过 300 行；配置保持同一 Host 配置职责，不为行数拆出转发模块。

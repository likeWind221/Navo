# 168：BUG-036 ChatGPT 凭据刷新被 HTTP 403 拒绝

日期：2026-10-27。状态：仅排查，未修复；根因未证实。该项登记外部认证链失败事实，不把它断言为模型、Renderer 或本地账号记录损坏。

## 现象与复现

F5.4 的正式 Electron + Kernel Host 真实验收采用隔离 NAVO_HOME 与已有凭据副本、openai / gpt-6-luna。前两个 Main Turn 均以 AUTH 失败，消息为 `ChatGPT authentication failed (token-request-failed). Run pnpm chatgpt login.`。没有模型正文、工具执行或路线创建，F5.4 真实门禁未通过。

现场 `%TEMP%/navo-f54-real-3427f895` 保留；会话可视化目录 `f54/real/auth-failure.json` / `auth-diagnostic.json` 保存脱敏证据。没有输出或上传凭据内容，没有登录、退出或修改默认账号。

## 已证实事实与根因假设

- 隔离库存在 2 个 llm-requested、2 个失败 Turn、2 个 AUTH 错误；失败发生在 OpenAIAdapter 取得 token 之前，未发出模型生成请求，不把 2 次持久调用尝试说成 2 次成功生成。
- 隔离账号记录仍为 connected 且有凭据，只代表本地记录状态，不证明服务端仍允许刷新。
- 另一次零生成诊断调用现有 ChatGPTAuth.accessToken，并只记录端点响应状态及内容类型：HTTP 403，application/json，cf-mitigated 为空；没有拿到更具体的服务端拒绝原因。未将 403 直接解释成凭据过期、权限撤销、网络或账号封禁。
- 真实 QA 首版仅等回合终止，未拒绝失败终态，导致第一回合失败后仍发出确认，再等待路线。该未合并脚本缺陷已退回 F5.4 子 Agent 修正；不是后端已经创建路线却漏刷页面。

## 修复内容

仅排查，未修复。已停止这一次 QA 的已确认进程树，保留失败数据库和日志，不复用失败库补跑。没有修改生产认证、代理、远程服务或账户配置。

## 验证结果与边界

已确认正式 Host 的失败事实与认证 HTTP 状态；尚未确认拒绝原因、重新授权是否有效，未完成真实 Main 复述 / 确认 / 规划。受控 Renderer 与离线检查只能证明界面链路，不能关闭本项或替代真实验收。

## 2026-10-27 补充诊断：网络出口

- 当前网络直连 `https://auth.openai.com/.well-known/openid-configuration` 返回 HTTP 403；本地账号仍为 connected，未登录、退出或修改凭据。
- 通过临时干净出口节点访问同一端点返回 HTTP 200；使用该出口执行 `pnpm chatgpt models`，凭据刷新成功并返回模型目录（包括 gpt-6-luna），未发起任何模型生成。
- 因此 403 与当前出口路由 / IP 相关，而不是本地账号记录或凭据文件损坏；服务端具体拒绝原因仍未确认，不能把“换出口可用”断言为服务端策略。
- 临时代理配置和凭据只在本次诊断期间存在，已停止并删除；没有修改默认账号、生产代理或代码。
- 真实 Main 两回合仍未运行；#111 保持 Draft，等待用户授权真实模型预算和可用的干净出口后再验收。

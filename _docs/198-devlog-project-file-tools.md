# Main 和 Node 文件系统工具

## 做了什么

按用户要求，Host 启用文件工具时，Main、Main 复盘和 Node 的工具列表开放 read、write、edit、shell；Host 未配置文件能力时不添加这些工具。更新压缩预检对能力字段的调用，不改变项目会话绑定。

## 关键决策

复用现有文件工具及项目工作目录解析：文件工具继续使用项目绑定与现有路径检查；shell 以项目目录为初始工作目录，但不是工作目录沙箱，命令具备当前系统用户的权限。读写工具的既有读取观察和覆盖条件不变。

## 验证与边界

Windows 本机 Node 22（工程声明 Node >=24）：`pnpm typecheck` 通过；定向测试 3 文件、7 项通过，包含 Mock LLM 分别驱动 Main 与 Node 在绑定项目目录写入文件。未进行真实模型的文件工具调用或用户桌面验收。

完整后端测试 188 文件中 186 通过、2 失败；1169 项中 1151 通过、18 失败。17 项来自 Host 进程测试，其中崩溃恢复明确报告 `host-already-running`，其余有 Host 未就绪；同时有一项资源处理测试超过 5 秒，具体原因未确认。测试后只读检查发现用户的 Electron 开发服务与 Navo Host 仍在运行，没有停止它们；不能据此断言所有失败均由占锁导致。当前 head CI、完整本机通过及 PR 均未完成。

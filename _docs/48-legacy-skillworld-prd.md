# SkillWorld 简化 PRD：DAG 自主规划 Agent 系统

**版本：** v0.6（单 NodeSession 与可编辑内容面板）
**日期：** 2026-09-03
**定位：** 系统核心是一个基于 DAG 的自主规划 Agent 系统，不绑定任何具体应用域；首个应用是技能学习 Agent。

---

## 1. 一句话描述

给定一个目标，系统自主调研、把它拆解为能力依赖图（DAG），逐节点执行并验证，并根据执行结果自主修订图，直到目标达成。

在技能学习应用中：

- 目标 = "掌握某项能力"
- 节点 = 一个能力单元
- 边 = 能力间的前置关系
- 验证 = 可检查的能力证据

## 2. 核心思想

1. **DAG 是活的计划**：不是预设的课程表，而是 Agent 产出的，且可以在执行过程中持续变化。
2. **规划 → 执行 → 验证 → 再规划**：系统的主动脉。
3. **完成由可验证的证据决定**，不由 Agent 自评。
4. **图的变化有版本、可追溯**：任何时候都能回答"计划为什么变了"。

## 3. 功能架构

| 层 | 职责 | 产出 |
|---|---|---|
| Goal（目标） | 接收并规范化用户目标 | 标准化目标描述 |
| Research（调研） | 围绕目标获取领域知识，组织来源 | 带来源的知识材料 |
| Planning（规划） | 将目标拆解为 DAG；执行中依据验证结果修订图 | 图版本（节点、前置边、修订理由） |
| Execution（执行） | 按依赖顺序执行节点；学习应用在节点内生成、练习和修改学习内容，再将证据交给验证边界 | 节点执行结果 |
| Verification（验证） | 依据可检查的证据判定节点是否完成 | 通过 / 失败 + 失败原因 |
| Record（记录） | 持久化图版本、执行与验证记录 | 可审计、可重放的轨迹 |
| Interaction（交互） | 向用户呈现图，允许查看、确认、干预 | 人机协作记录 |

```text
              User
               ↕
           Interaction
               ↕
Goal → Research → Planning ⇄ Execution → Verification
                  ↕               ↕
               Record（贯穿所有层）
```

## 4. 主循环

```text
Goal
  → Research
  → Planning：产出 DAG v1
  → Loop：
       执行下一个可执行节点
       → Verification
       → 通过：标记完成，解锁后继节点
       → 失败：Planning 修订图 → v2（增 / 删 / 调节点）→ 回到 Execution
  → 全部关键节点完成：目标达成
```

要点：

- 失败后的默认动作不是"重做同一节点"，而是"先修订计划，再重新执行"。
- Planning 可以随时向 Research 追加调研请求，不必一次性调研完。

## 5. 核心原则

1. **规划与执行分离**：Planning 只产出和修订图，Execution 只执行图，互不越权。
2. **证据驱动**：节点只有依据可检查的验证结果才能标记完成。
3. **图版本化**：每次修订产生新版本，旧版本不销毁，可回滚、可重放。
4. **再规划是一等能力**：改计划和执行节点一样，是日常动作而不是例外。
5. **自主度可调**：不同种类的图变更（全自动 / 需人确认）可按目标配置。
6. **核心与应用无关**："规划 → 执行 → 验证 → 再规划"循环不依赖学习域；学习只是它上面的一个应用层。

## 6. 首个应用：技能学习 Agent

### 6.1 产品目标

技能学习 Agent 帮助用户把“想掌握某项技能”转化为一组可学习、可练习、最终可验证的能力节点，并在持续交互中推进这些节点。

学习应用遵循系统核心的规划、执行、验证和再规划边界，但不会把一次讲解、一次练习或 Agent 的自我评价直接视为能力已掌握。

### 6.2 产品术语

#### 能力节点（Node）

一个 Node 表示单一、可描述且最终可验证的能力单元。它回答“用户需要能够做什么”，而不是“系统要展示哪一章”。

能力节点：

- 可以包含能力目标、前置关系、局部学习状态、练习记录和掌握结论的引用；
- 可以经历多次讲解、提问、练习和回顾；
- 不等同于课程章节、一次任务、一次对话、一个 Turn 或某种具体 DAG 数据结构；
- 只有后续 Verification 根据可检查证据才能确认其 mastery，不能由 NodeAgent 自评完成。

#### MainSession

MainSession 是围绕整个学习目标的主协调会话。它承载用户与 Main Agent 对目标、路线和全局进展的持续讨论。

MainSession 不充当所有节点对话的共享日志，也不复制各 NodeSession 的完整内容。

#### NodeSession

每个 Node 绑定一个独立、持续的 NodeSession，作为用户与 NodeAgent 围绕教材和练习题协作的统一对话记忆：

- 同一 Node 在其生命周期内复用同一个 NodeSession；
- 教材生成、习题生成、答疑和内容修改共享该 Session 的多轮上下文；
- 不同 Node 的 NodeSession 相互隔离；
- 教材与习题是 Node 的领域内容，不是额外的对话 Session；
- Node 与 Session 是不同身份：Node 保存学习领域事实和内容，Session 保存模型交互事实。

绑定关系必须可记录和恢复，但本文档不规定数据库、文件格式或内存结构。

### 6.3 教材与练习内容面板

每个 Node 可以包含教材与练习题两类可编辑领域内容。它们可以在界面中显示为两个面板，但不是两条 Session，也不是互斥阶段。

- 教材面板保存当前纯文字教材及来源；
- 练习面板保存当前题目和供判题使用的参考答案，其中参考答案默认不向学习者展示；
- 用户在统一 Node 对话框中可以答疑，也可以要求修改教材、重写题目或同时调整二者；
- 每次 NodeAgent 调用可以读取两个面板的最新内容和同一 NodeSession 的对话历史；
- 教材与练习内容必须通过结构化领域操作提交，不能依赖解析 assistant 自然语言来更新；
- 生成教材或习题不蕴含能力已掌握。

具体界面可以使用面板、画布或其他方式展示，产品契约不绑定 UI。

### 6.4 Main Agent 与 NodeAgent 权限边界

#### Main Agent

Main Agent 负责全局协调：

- 澄清和维护总体学习目标；
- 发起调研与规划，并管理 Road Map、DAG 及其版本；
- 选择或调度应处理的能力节点；
- 汇总节点结果、Verification 结论和跨节点建议；
- 决定是否接受前置缺口提议并触发再规划。

Main Agent 不直接写入 NodeSession，不伪造节点练习或 Evidence，也不能绕过 Verification 宣布节点已掌握。

#### NodeAgent

NodeAgent 只在一个 Node 的边界内工作：

- 围绕当前 Node 生成和修改教材、练习题，并进行答疑和练习反馈；
- 使用本节点目标、来源引用、当前内容面板和 NodeSession 上下文；
- 通过结构化领域操作记录或提交本节点的局部产出与发现；
- 发现前置能力缺口时提出 proposal，交由全局规划边界处理。

NodeAgent 不能直接修改 Road Map 或 DAG，不能修改其他节点，不能读取其他 NodeSession 的完整对话，也不能凭自身判断提交最终 mastery 结论。跨节点影响必须通过可审计的领域事实或 proposal 表达，而不是 Agent 间直接通信。

### 6.5 NodeAgent 与无状态 Grader 决策

当前版本不把 Tutor 与 Assessor 拆成两个长期 Agent。一个持续的 NodeAgent 使用单一 NodeSession，负责教材、习题、答疑、修改和形成性反馈。

具体练习的批改由无状态 Grading Service 执行：每次只向一次独立 LLM 调用提供题目原文、参考答案和学习者答案，不加载 NodeSession 历史，也不保留跨批改记忆。Grader 的结果仍不等同于最终 mastery；未来 Verification 应根据已提交 Evidence 作受限、可重放的判定。

### 6.6 当前应用边界

上述契约只定义产品身份、职责和交互语义，不规定：

- Web、CLI、画布或其他 UI；
- 模型提供商、模型数量或 Prompt 的具体文本；
- 内存、文件、数据库或远程存储；
- 资料检索提供商、RAG、教材存储形态、出题、评卷和 mastery 算法；
- Road Map 与 DAG 的具体数据结构和调度策略。

## 7. 与 v0.2 PRD 的关系

- 原 PRD 的学习域内容（能力契约、Stage、verifier、asyncio 主题）从“系统要求”降级为“第一个应用的素材”。
- 原“白名单约束规划”升级为“自主规划 + 自主度可调”。
- v0.6 将 Node 交互收敛为一个持续 NodeSession，并把教材与练习题定义为可编辑领域内容；练习批改使用不加载对话历史的无状态 LLM 调用。具体持久化、验证实现和页面交互仍由后续设计确定。

# F1.2.1 最小视觉样板（待视觉确认）

## 做了什么

- 新增语义 CSS tokens、三个自绘 SVG 操作图标，以及使用 CSS Modules 的最小样板页。
- 样板包含色板/字体、按钮/标签、卡片、输入框和静态对话；主按钮反馈、重置和草稿编辑只改变本地状态。
- 开发模式通过懒加载展示样板，生产默认入口保留占位，不组合演示数据。
- 设计规范更新至 v1.1：地图地块后续采用 3D 建模，当前不制作 SVG 地形，也不引入 3D 引擎。

## 关键决策

- 不提前抽象通用组件库；仅独立复用图标，样板控件留在预览目录，选定后按真实工作区需求提取。
- 控件使用原生按钮、标签和 textarea，发送禁用且说明原因；不伪造 Agent 行为。
- 自定义操作图标统一 24×24 网格、1.75px 描边；颜色来自 CSS tokens。

## 坑与发现

- typecheck、Electron 构建、独立浏览器构建通过，开发服务器已返回自动 JSX runtime 的样板模块；没有新增依赖。
- 生产构建不包含样板动态模块。所有本次手写文件小于 300 行。
- 尚未进行浏览器截图、实际视口与键盘验收；构建和 HTTP 返回不替代人工视觉确认，因此步骤保持进行中。

### 编辑器配置修正

- 用户反馈 VS Code 中 React import 报错；检查发现前端缺少标准命名 `tsconfig.json`，命令行却通过 `-p` 显式加载 web/node 配置，存在编辑器与 CLI 配置发现不一致。
- 新增 `frontend/tsconfig.json` 作为 solution 入口，以空 files 和 references 指向原有两套配置，不扩大后端编译范围，不合并 DOM 与 Node 环境。
- 分环境 typecheck、入口配置解析和 Electron build 通过；入口无源码，单独检查入口不等于检查引用项目，日常仍使用 `pnpm typecheck`。
- 尚未获得 VS Code 的具体诊断文本或语言服务日志；需要重启 TypeScript 服务并确认 TSX 文件归属 `tsconfig.web.json`，若仍报错再根据错误码排查。

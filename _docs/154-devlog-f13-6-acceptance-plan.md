# 154：F13.6 完整任务验收计划

> 日期：2026-10-26
> 状态：验收目标与范围冻结；实施前仍需按仓库流程拆分可独立验证的工作，不自动运行真实模型或 GPU 实验。

## 目标

验证 Navo 的项目资料库不仅可以保存、组织和检索资料，而且能够被 Main / 多个 Node 在真实的长程任务中按需使用，产生成果，并由 Main 基于 Node 目标、完成标准、报告和可访问资料进行审查。

F13.6 是 F13 当前计划中的最后一个端到端验收阶段。它不以新增工具或模型为目标；重点是确认现有 Project / Roadmap、Main / Node、Resource、混合检索、Turn Context、取消和恢复机制能够组成完整工作流。

## 当前基线

- F13.3d 已提供权限内混合与图局部检索。
- F13.4a 已提供统一 Turn Context；F13.4b Working Board 不单独实现。
- F13.4c 已合入 master（PR #98，提交 `4de60fe`）：`list_resources`、`search_resources`、`fetch_resource` 按需工作；全量目录注入和动态 Resource ID enum 已移除。
- F13.5 独立成果引用 / 来源追踪于 2026-10-26 按用户决定取消，不是 F13.6 的前置条件。
- F13.1 / F13.2 的正式 Renderer 页面与交互仍未完成。F13.6 必须如实区分后端、Bridge 和正式 UI 的状态；若正式页面尚未交付，不得宣称完整桌面产品验收通过。

## 验收主流程

```text
Human 提供 Project Goal
        |
        v
Main 规划 Roadmap 并启动 Node
        |
        v
Node 根据自身目标执行任务
        |
        +--> list_resources 浏览可见资料
        +--> search_resources 检索相关内容
        +--> fetch_resource 按需阅读原文
        |
        v
Node 发布成果 / 提交完成信号
        |
        v
Main 获取报告、目标、完成标准与相关成果
        |
        +--> 确认完成
        +--> 提出返工
        +--> 跳过 / 请求 Human 决策（按现有生命周期规则）
        |
        v
检查成果、权限、错误与恢复行为
```

以上流程复用现有 ProjectRuntime、Roadmap、AgentRuntime、Session、Resource 与 Main Review 机制；不增加第二套 Runtime、证据评估模型、独立引用追踪、自动唤醒或固定的检索调用状态机。

## 验收场景

| 场景 | 主要验证 | 通过标准 |
|---|---|---|
| 跨资料任务 | 一个 Node 需要从多份资料检索、读取、综合并发布成果 | 工具选择与任务信息缺口相符；引用到的事实可由实际读取内容支持；不把文件元数据当成已读正文 |
| 多 Node 协作 | 不同 Node 分工完成子任务，Main 负责汇总和审查 | Node 只访问授权资料和自身任务信息；通过现有报告 / Resource / Mailbox 交接；没有跨 Node Session 直连 |
| Main Review | Node 提交成果，Main 对照目标、完成标准、报告和可用成果进行判断 | 能给出完成、返工、跳过或交由 Human 决定的有效结果；返工反馈进入后续 Node Turn |
| 信息不足与冲突 | 搜索无结果、只命中文件信息、正文不可读、资料间内容冲突 | Agent 区分空结果与检索错误；说明信息缺口；必要时继续搜索 / 读取；不编造资料结论 |
| 权限隔离 | 私有、定向共享、Project public Resource，以及不同 Node / Main Review | 不泄露无权资料的名称、片段、正文或关系来源；猜测 Resource ID 不绕过 ACL |
| 失败与取消 | Embedding 未配置、索引过期、工具执行失败、用户取消 Turn | 错误语义可区分；取消传播到检索；不把失败伪装成无结果、不因资料变化自动启动新 Turn |
| 重启恢复 | Resource 索引 / Session / Main / Node 状态在应用重启后恢复 | 已提交状态可恢复；中断 Turn 不会未经 Human Action 自动续跑；已删除资料不再通过当前目录 / 检索 / 读取返回 |
| 产品入口 | 正式 Renderer 中导入、整理、搜索、打开资料及查看 Agent 使用过程 | 仅在正式 UI 实际可用并完成交互验收后标记通过；Bridge 调用和后端测试不能代替 Renderer 验收 |

## 验收证据分层

1. **离线后端测试**：typecheck、完整测试套件和必要专项脚本；记录确切测试数、失败与环境。
2. **真实模型任务**：至少覆盖一次跨资料多 Node 任务与 Main Review；记录模型、请求数、耗时、成本 / 额度、工具调用轨迹和结果。运行前单独报告预估耗时、额度与影响，取得用户授权后执行。
3. **Bridge 实际调用**：验证版本化契约、参数校验、错误、取消与权限。现有管理 Bridge 结果不代表搜索或正式 UI 已通过。
4. **正式 Renderer**：资料库、搜索和 Agent 资料使用过程的真实页面交互；由前端实际交付后验收。未完成的 UI 明确标记为阻塞或待验收，不得以 mock 替代真实产品结论。

- 不新增独立证据评估模型，不要求模型暴露隐藏推理。
- 不重做检索算法、Embedding Provider、图谱构建或 Resource ACL。
- 不创建 Working Board、第二套 AgentRuntime、自动唤醒或强制工具调用顺序。
- 不因 F13 后端测试通过而自动标记 F13.1 / F13.2 正式 Renderer 已完成。

## 完成标准

- 上表的后端任务场景、权限、失败、取消和重启场景均有可重复的验证证据。
- Main / 多 Node 的端到端任务能够使用资料并交付可审查成果；Main Review 与现有 Human Gate 语义一致。
- 离线、真实模型、Bridge、Renderer 的结果分别记录，明确哪些通过、未运行、被阻塞或不适用。
- 所有新发现的问题进入现有 Bug / 开发记录；不为追求阶段收口而隐藏失败或扩大测试结论。
- 在正式 Renderer 依赖未完成时，只能声明后端 / 已验证层通过，不得声明完整桌面产品验收通过。

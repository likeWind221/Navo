# F12.3 摘要压缩与 Session 检查点

> 日期：2026-10-17  
> 状态：✅ 已完成；2026-10-18 补齐本机完整验证与历史 PR CI 核对
> 范围：在 F12.2 压力触发后执行本地结构化摘要压缩，使用独立检查点事件替换模型可见历史，保留原始事件日志；不实现 provider 超窗恢复（F12.4）或桌面公共契约（F12.5）。

## 做了什么

- 新增压缩前缀选区、结构化摘要生成和压缩协调模块。
- Session surface 新增独立的 compaction-checkpoint 消息事件；检查点以 surface replace 替换所选前缀，原始用户/助手/工具事件仍保留在日志中。
- 在真实模型请求前等待压缩完成，成功后重建请求并重新测量上下文；最多执行两轮压力压缩。
- 新增选区、工具调用/结果边界、检查点回放、stale selection、压力触发、多次累积压缩和摘要失败不改写历史的离线测试。

## 关键决策

- 摘要使用当前请求路由的模型，不暴露 Agent 工具；历史中的工具调用与结果在辅助摘要请求中转成文本，避免无工具声明时破坏协议合法性。
- 摘要格式覆盖目标与用户约束、事实与证据、决策及理由、进度、错误修正、文件和下一步；重复压缩时显式合并旧检查点。
- 压缩仅选择 surface 头部的可压缩前缀，并同时受近期尾部预算、摘要输入容量和完整工具配对约束。
- 与 F12.0 早期“压缩失败后继续原请求”的默认描述相比，本 Step 采用用户随后确认的 fail-closed 语义：压缩失败不修改 surface；若请求仍超过压力阈值，则以明确失败退出，不盲目发送可能超预算的请求。
- 检查点提交前验证完整 surface snapshot 与 generation；若摘要期间 surface 发生变化，拒绝安装过期摘要。覆盖边界是 surface 顺序中的事件序列引用，不要求数值递增，因为新检查点会以较新的事件序列插入历史头部。
- 摘要请求使用现有模型重试与取消机制，但不追加普通 llm-requested 事件，避免污染 Session Meter 的 usage 锚点。

# F13.0 项目资料库产品设计

> 日期：2026-10-18，2026-10-19 完成收口
> 状态：用户已确认整体设计并要求收口、推送，F13.0 完成。F13.1 及后续在新会话单独启动，本会话不实施。

## 做了什么

用户要求逐部分设计。本记录汇总已确认的产品规则，并记录检索时机的公开架构与论文对照；仅修改文档，不修改生产代码、不运行模型实验。

### 已确认的资料管理规则

- 一个项目拥有一个资料库，基于本项目 Resource 集合组织，不另建冲突的资料身份体系。
- 不强制按用户资料 / Agent 产物分类。每份资料展示最初创建者（用户、Main 或具体 Node），后续编辑或替换不改变创建者；创建者不代表可信度，也不直接等同于修改权限。
- 名称默认文件名；格式由系统识别；描述由用户选填，可空，不自动生成。首版不使用标签。
- 支持选择多文件、拖拽和整目录导入，递归保留目录结构。用户导入的资料默认项目内全部 Node 可用，不开发限制管理界面；Agent 发布的 Resource 保留既有权限。
- 保存文件副本，沿用 Agent 发布 Resource 的项目存储方式 `.navo/assets/<resource-id>/`。资料库中的文件夹及相对路径表示组织位置，与实际内容存储分别管理。
- 支持文件夹、子文件夹与资料移动；Agent 发布资料默认进入根目录。同目录内文件 / 文件夹重名自动添加 (1)、(2) 等编号，文件编号放在扩展名前；不同目录可同名，每份资料有独立 Resource ID。
- 支持替换文件，保留 ID、名称、描述和访问范围。正文重新处理期间不返回旧正文的检索结果；已有引用显示来源已更新。首版不保存旧正文版本，不做完整修改历史或版本恢复；保留来源、加入时间与最后更新时间。
- 用户可以删除项目内任意资料，包括 Agent 发布的 Resource；删除后不再检索或读取，已有引用显示来源已删除。删除非空文件夹须提示并确认连带删除所有后代文件夹和资料，取消不修改。
- 所有文件均保留，不以是否支持正文检索作为入库门槛。首版正文检索范围为 TXT、Markdown、可提取文本的 PDF；其他格式仍可按名称、相对路径和描述查找，Agent 依现有工具能力按需读取。保存成功不等于能读取或理解正文。
- 文件保存后立即出现在资料库，后台处理正文；区分处理中、可检索、仅文件信息可搜索、处理失败，失败保留文件并显示原因。

### 已确认的用户与 Agent 操作边界（2026-10-19）

- 用户可管理项目内全部资料：导入文件或目录，修改名称和描述，替换、移动、删除资料，以及创建、重命名、移动和删除文件夹；首版不提供访问权限编辑界面。
- Node 直接沿用当前 Resource 工具的能力与权限，不按用户管理范围扩大 Node 权限，也不因资料库改版收缩既有能力。发布、查询、读取、修改元数据、删除等操作仍遵循现有工具与所有者规则；Main 的既有能力与权限同样保留。
- 本阶段不为 Agent 新增目录导入、文件内容替换、文件夹管理或资料移动工具。检索能力另按 F13 已确认范围新增，并遵守现有可见性规则。
- 用户编辑或替换 Agent 发布的资料不自动转移所有权，原 Agent 仍按既有规则管理该资料；创建者标记与操作权限分别表达。

### 已确认的页面入口与操作（2026-10-19）

- 项目工作区提供“资料库”入口，默认进入该项目资料根目录。顶部提供文件夹路径导航、搜索框、导入文件、导入目录和新建文件夹操作；主区域展示文件夹与资料卡片。
- 资料卡片显示名称、格式、创建者与处理状态，搜索结果额外显示资料库相对路径。单击资料打开右侧信息面板，不预览正文。
- 信息面板展示名称、选填描述、创建者、相对位置、格式、加入时间、更新时间、处理状态及失败原因。资料操作包括重命名、编辑描述、移动、替换文件和删除；文件夹操作包括重命名、移动和删除。
- 查看文件的按钮命名为“用系统默认应用打开”。沿用本轮提出的副本查看语义：系统应用打开查看副本，外部编辑不自动回写资料库，更新库内内容仍通过替换文件完成。打开失败应展示可读原因。
- F5.7 的 Resource 元数据查看与资料库信息面板使用同一份资料信息，F5.7 本身不扩展为文件管理或正文预览。

### 已确认的导入与处理异常体验（2026-10-19）

- 批量导入部分文件保存失败时，保留成功部分，列出失败文件及原因，支持重试失败项；重试不重复导入已成功项目。
- 用户取消导入时保留已保存文件，停止尚未完成的导入；已保存文件继续处理正文。结果明确区分已保存、失败与已取消项目。
- 文件保存成功但正文处理失败时，保留文件，仍可用系统默认应用打开并按文件信息搜索；显示失败原因，提供“重新处理”。
- 应用关闭或重启打断正文处理时，下次启动继续处理已保存的文件；不把处理中断显示成正文已可检索。
- 替换的新文件保存失败时原资料保持不变；新文件保存成功但正文处理失败时保留新文件，显示处理失败，不恢复旧正文检索结果。首版仍不提供旧正文版本恢复。

### 已确认的搜索与引用体验

- 默认搜索整个项目资料库，可限定当前文件夹及其子文件夹；Agent 默认搜索本项目内自己有权访问的资料，也可限定文件夹。不得泄露无权资料的名称、片段或正文。
- 前端搜索结果采用文件卡片网格，每份资料一张卡片，显示名称、格式和资料库相对路径，可定位所在文件夹。首版不做正文预览，不默认生成综合回答。
- 同一文件命中多个片段时前端仍只显示一张卡片，Agent 可以获得多个相关片段。
- Agent 搜索结果提供相关正文片段、Resource ID、名称、相对路径和可用来源位置，支持进一步读取；无正文检索能力的资料只返回文件信息，明确尚未读取正文。
- 对用户展示文件级引用，仅显示资料名称，不展示页码或行号；按 Resource ID 关联并定位资料库。移动 / 重命名不破坏关联，替换 / 删除分别提示来源已更新 / 已删除。
- 只读到文件信息不能据此声称正文支持结论。文件级引用不提供段落级核验，用户需自行打开原文件核对；前端不展示位置不等于检索内部可以失去片段与来源的对应关系。

### 已确认的搜索刷新与资料变化（2026-10-19）

- 搜索结果分批加载，提供“加载更多”；处理中资料不阻断已有结果，提示部分资料尚未完成正文处理。
- 导入、替换或处理完成后更新资料状态，提示搜索结果有变化；由用户点击“刷新结果”，保留查询词和搜索范围。
- 重命名或移动后更新名称与路径，引用继续通过 Resource ID 关联。点击已删除资料时提示“资料已删除”，允许刷新结果。
- Agent 搜索后、继续读取前资料被替换时，明确返回“资料已更新”，重新读取当前内容，不把新旧片段当作同一版本拼接；读取过程中发生替换时，已开始的单次读取固定到开始时的资产代次，可完整返回该代次内容，不得混合新旧版本；具体实现机制由 F13.1a 收口。
- Agent 已读内容随后被替换或删除时，已进入对话的内容保留，已有引用标注来源已更新或已删除；后续检索与读取遵循当前状态。删除不能撤回已进入对话的文字。并发语义：删除提交后拒绝新读取；删除提交前已登记读取租约的单次读取允许完成并返回固定代次内容，物理清理等待在途读取释放租约。首版不提供在途读取的即时撤权。

## 关键决策：采用 Agent 驱动的按需检索

本轮用户授权：若符合公开工程或论文设计则固定，否则调整后给出理由。采纳如下产品主线，具体检索算法、模型和契约仍未选定。

1. 检索与读取作为现有 Main / Node 在已授权 Turn 内可用的能力，由任务模型根据目标与已读证据选择搜索、继续读取、改写查询、补充查找或继续执行。具备可用正文时可直接读取，不强制每次先搜索。
2. 用户明确要求查项目资料，或结论需要以项目资料为依据而上下文没有相应证据时，必须查阅；不以模型觉得自己知道答案作为免查理由。若引用当前上下文中已读证据，不要求无意义重复检索。
3. 搜索无结果不等于资料库没有答案；处理中、仅文件信息可搜索和读取失败必须与事实性不存在区分。有明确文件线索时可按工具能力继续读取，否则报告具体信息缺口。
4. 搜索与阅读可随任务反复进行，不固定为先检索一次再生成。由现有 Turn 生命周期控制权限、取消和执行预算，不创建独立的无限检索循环，不因资料到达唤醒 Agent。
5. 任务模型可以判断当前证据是否足够继续工作，但这不是 Node 完成判定；既有 Human / Main 审查边界保持不变。取消、预算用尽或仍有证据缺口时明确停止原因与未完成项，不为收尾编造结论。
6. 用户能查看查询、命中资料、读取与终止状态等实际操作；不要求展示模型隐藏推理。
7. 用户已决定首版不做独立证据评估，不接入 Jev 类决策模型或增加独立证据评估环节。Main / Node 仍需根据已读内容判断是否补查、说明冲突与缺口；这不等于新增独立评估服务。下方调研仅保留为历史候选，不纳入实施依赖，不预建插件或配置。

主流程（文字）：已授权任务 → 判断信息缺口 → 在权限范围内选择搜索或读取 → 观察实际返回证据 → 继续查阅或执行任务 → 引用已使用资料并报告缺口。权限、取消和预算由既有执行边界控制。

### 调研依据与取舍

- [Microsoft Agentic RAG 架构](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-agentic)：将检索作为工具，Agent 决定调用并评估中间结果。采用工具驱动与迭代原则，不引入其云服务依赖。
- [LangChain Retrieval](https://docs.langchain.com/oss/python/deepagents/retrieval)：区分固定两步、Agentic 和混合架构。采用自主调用方式；不据此宣称全部行业系统都如此设计。
- [A-RAG，2026 预印本](https://arxiv.org/html/2602.03442v1)：向同一 Agent 暴露关键词搜索、语义搜索与片段阅读，交错执行。采用搜索与阅读可分别选择的产品原则，不机械照搬工具数量、分块参数、去重策略或预算耗尽时强制合成答案；其问答结果不证明 Navo 已有效。
- [Search-R1，2025](https://arxiv.org/abs/2503.09516)：研究训练模型交错推理与多次搜索。支持该交互方向已有研究先例，不采用其强化学习训练方案，不承诺未经训练的 Navo 模型拥有相同效果。
- [Adaptive-RAG，NAACL 2024](https://aclanthology.org/2024.naacl-long.389/)：小模型按问题复杂度选择不检索、单次或迭代检索。证明独立路由是一条可研究路线，不证明在 Navo 上优于已有任务模型。
- [TypeSafe 官方文档](https://docs.typesafe.ai/introduction)：Jev 负责范围明确的选择、评分及是非判断。该职责适合局部辅助决策，结构化结果不能作为判断必然正确或整体更省成本的证据。
- Harness：历史文档指向的本地 deepseek-harness 目录在当前 checkout 不存在，本轮改为只读核对官方 master 的 [agent.ts](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/src/agent.ts) 与 [tool-calls.ts](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/src/tool-calls.ts)。采用既有 Agent 循环、结构化工具结果和取消归属的原则；不移植其当前完整队列、插件装配或自主唤醒机制，不称其已提供 Jev 路由。该在线引用非固定源码快照，技术落地时须核对具体版本。
- 对照本机 `src/agent/runtime.ts` 的 Turn 执行、取消与 maxSteps：产品要求复用现有生命周期，不据此声称检索工具已实现。

## 坑与发现

- Agentic RAG 是公开架构方向，非统一行业标准；采用该方向不等于创新或效果已验证。
- 必经独立决策模型会增加一次判断和失败边界，且其不检索判断可能阻断需要的证据；首版保留任务模型控制，避免两个控制者争夺下一步决定权。
- 资料未进入当前上下文时，任何模型都不能仅凭自信确定库内没有答案；需要依实际检索 / 读取结果形成结论。
- 既有 124 规划中的标签与正文预览目标被本轮用户决策修订：不做标签、不做正文预览，组织方式改为文件夹，引用为文件级。后续阶段计划须按已确认范围同步。

## 验证结果与边界

- 仅做公开资料调研、当前源码只读检查及文档检查，未运行模型、GPU、测试或新增 API；不形成 Navo 效果结论。
- 未实施独立决策模型。若后续重新考虑 Jev，需与同任务、同资料、同权限及可比预算下的任务模型自主检索对照，检查漏查、无效检索、任务依据、总时延与总成本；另行授权后才运行。

### 对 Navo 的候选建议（未采纳为实现范围）

- 优先研究检索后的证据评估：Main / Node 提出问题 → 权限内召回 → 决策模型评估候选与问题的关系 → 返回原文、来源及评估信号 → 原任务 Agent 决定阅读、补查或继续。首个切入点只做候选相关性 / 证据关系，不同时部署多个独立门控。
- 不设检索前 Jev 一票否决，不自动丢弃相反证据，不让单一分数批准 Node 完成。评估支持、冲突、无关与不确定的作用必须分别定义；冲突是需要阅读的线索，不能简单作为低分噪声过滤。
- 证据充分性与自动停止可作为后续独立诊断；不与首个候选一次性实施。其误判可能过早结束检索，且公开项目的概率校准和省钱结果均不稳定。
- 展示价值应来自可核对的决策过程和实际收益：用户能看到哪些资料被采用、哪些存在冲突、为何继续查阅的操作状态；不要求暴露隐藏推理，不将“加一个新模型”本身作为创新结论。
- 对照至少包括同召回池的原始排序、专用重排器、任务模型自身判断与 Jev 判断；涉及级联须有同预算随机选择控制，分别报告召回损失、错误剔除、错误停止、依据正确性与端到端成本 / 时延。这里只定验证问题，具体协议及运行另行授权。
- Jev 以外的候选包括 [OpenJev-1.7B](https://huggingface.co/alanhuangya/OpenJev-1.7B) 与 [JEVal / InnerJev 研究](https://arxiv.org/abs/2610.03935)。前者模型卡明确主要为英语且未直接对比 Jev，后者是通用决策研究，均不证明中文资料库检索效果。模型选择保持开放，不部署或训练。

## 已确认的前后端交接与验收（2026-10-19）

### 职责与交付边界

- 后端负责文件保存、组织与权限、正文处理、检索、Agent 工具及引用关联；前端负责资料库页面、操作反馈、搜索卡片、资料信息面板与任务查阅记录。后端实现交由 backend-plan.md 实施，前端通过公共契约消费，不直接依赖私有 Store、Cordis Context 或内部事件。
- 桌面需能查询目录、资料详情、处理状态及分页搜索结果，发起已确认的导入、取消导入、元数据修改、组织、替换、删除和重新处理操作，并跟随处理进度与资料变化。用系统默认应用打开由桌面完成，打开前需确认目标资料当前可用。
- F13.2b 提供资料浏览管理的桌面交接，F13.3b 提供搜索与继续读取的桌面交接，F13.5b 提供引用定位与变化提示的桌面交接。这些子步骤只交付公共能力及 Bridge，不代表 Renderer 页面已完成。
- 契约在对应子步骤技术设计中确定版本和字段，必须有运行时校验，明确错误、取消和兼容语义：取消导入保留成功项，取消查询或观察不撤销已保存资料；失败区分保存失败、处理失败、资料更新、删除或不可用，不向无权调用方泄露资料信息；分页或读取期间集合 / 内容变化不得静默造成重复、遗漏或新旧版本混用，需提供明确刷新或重新读取反馈。
- F5.4–F5.8 不因本设计改变状态与实施顺序。资料库元数据与 F5.7 保持同一资料信息；Main / Node 查阅过程和成果引用的正式 UI 验收依赖对应 F5 页面。整体视觉与交互细节在前端实施时审查，不把本产品规则文档作为正式 UI 验收。

### 验收场景

| 场景 | 输入与操作 | 预期结果 |
|---|---|---|
| 混合目录导入 | 导入含子目录、TXT / Markdown / 可提取文本 PDF 和不支持正文处理文件的目录 | 保留层级与全部成功保存文件；支持格式进入正文检索，其他格式可按文件信息查找并用系统应用打开；无自动简介 |
| 资料整理 | 新建文件夹，在同一目录导入同名文件，修改描述，移动、替换和删除资料，再删除非空文件夹 | 同名自动编号且 ID 独立；引用在移动后保持关联；替换保留资料身份并重新处理；递归删除前明确警告，取消不修改 |
| 用户搜索 | 用问题或术语搜索全项目，再限定当前文件夹；同一文件包含多处相关内容 | 结果为文件卡片，同一文件不重复展示，显示相对路径并可定位；支持加载更多、处理中提示及保留条件的手动刷新；不做正文预览 |
| Agent 资料任务 | 明确要求 Main / Node 根据项目资料完成跨文件任务，并设置需补查的信息缺口 | 按需搜索、读取和补查，能看到实际工具操作；成果只引用已使用资料，展示资料名称；未读正文不得声称正文支持，缺口和冲突需说明；不增加独立证据评估模型 |
| 资料变化与权限 | 读取前后替换或删除资料，移动带引用资料；以无权 Node 搜索和读取 | 不混用版本；旧引用显示更新或删除，移动后引用仍可定位；已读对话不撤回；无权资料名称、片段和正文均不泄露，Node 管理仍遵循现有 Resource 权限 |
| 失败、取消和重启 | 部分文件保存失败，正文处理失败，取消目录导入，在处理时关闭并重启应用，新文件保存或处理失败 | 成功部分保留且重试不重复导入；失败原因可读；处理可重试及重启续接；替换保存失败保留原资料，替换处理失败保留新文件且不返回旧索引 |

验收分别记录后端离线功能、Electron Bridge 实际调用、Renderer 正式 UI 与真实模型任务结果；任何一层通过不能替代其他层。资料不足、权限隔离、变化和重启必须纳入最终完整任务验收。真实模型任务运行前另报预计耗时、额度与影响并取得用户授权；本记录不构成运行授权。
